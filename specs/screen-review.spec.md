# Screen spec: Review (`review`)

**Source:** `renderer/src/views/review.ts`, `renderer/src/components/reviewControls.ts`, `renderer/src/reviews.ts`, `renderer/src/shortcuts.ts`, `renderer/src/components/toast.ts`, `renderer/src/components/popover.ts`, `renderer/src/components/roleIcon.ts`, `renderer/src/components/inlineLink.ts`, `renderer/src/views/matches.ts` (row menu's "Grade on Review"/"Edit match…"), `renderer/src/views/matchDetail.ts` (`openMatchEditorById`, the detail head's "Grade on Review"/"Delete match"), `renderer/src/matchActions.ts` (`deleteMatch`), `src/core/analytics/session.ts` (`groupByDay`), `renderer/src/format.ts` (`prettyDay`), `src/core/rankDisplay.ts` (`rankParts`), `src/core/dashboardData.ts` (`pendingReviewMatches`, `pendingReviewsRecent`, `eligibleForNoRead`, `toMatchRow` — `MatchRow.reviewed`), `src/main/dataProvider.ts`, `src/main/dashboard/ipcHandlers.ts`, `src/store/history.ts` (`setReviews`, `clearReviews`).

**Shared context:** Renders from a `DashboardData` snapshot via `ViewContext`; the sidebar shows a pending-review badge (`renderer/src/app/shell.ts`), scoped to the last 7 days (R1) — see Constraints.

## Intent

The home of the manual (◎) layer. Auto-tracking removes the "I'm logging this game" moment, so finished games land here as an inbox needing the human read: grade the active targets (Hit / Partial / Missed) and flag how the game felt. The auto (⚡) facts are read-only — the player only adds what the app can't see.

## Layout & behaviour

- **Pending inbox:** tracked games without a saved review; the first pending item is pre-expanded, the rest render collapsed. Derived from `DashboardData.reviewInbox`, which is always **unfiltered** (see Constraints).
- **Grouped by day (R3):** rows render under day headers (`groupByDay`, `prettyDay` — "Today" / "Yesterday" / a friendly date), newest day first, each stating its record and game count (`Yesterday · 2 games · 1-1`). The day holding the newest pending game is always expanded; older days start collapsed (their rows aren't mounted at all, only the header — "keeps the DOM small" on a deep backlog) and stay open once the player opens them, via a module-level `expandedDays: Set<dayKey>` that outlives a re-render the same way `gradedThisSession` does. Clicking a day header anywhere toggles it; its own "Mark as no-read" action clears just that day (see below). The account/hero/role/time meta line and the sibling Skip chain (below) both ignore day grouping — Skip walks the flat pending order across a day boundary, expanding the target day if needed.
- **Collapsed rows carry inline quick-grade (R2):** each collapsed row shows a compact H/P/M chip (`quickGradeChip`, `segmented segmented--tiny`) per in-scope active **self-rated (◎)** target, plus a Tilt toggle chip, alongside the usual **Grade** button that opens the full card. Grading every self-rated target shown (or, when the game has none in scope, toggling Tilt) auto-saves immediately — the common "already know how it went" case never needs the full card. SR, performance, comms and the other flags stay behind **Grade**.
- **Active-targets strip** (with a pointer to the Targets page when empty). "Active" is the user-selected set — `isActive && !archivedAt` — set on the Targets screen. The same in-scope self-rated filter backs both the collapsed quick-grade chips and the expanded card's target rows, so they can't disagree about which targets a match needs.
- **Per-game grading card:** a ⚡ auto-facts header (result, map, hero, role shown as a **role icon**, time, account — with the competitive rank composed through the shared rank renderer, `rankParts`, when shown) · a 3-way grade control per active **self-rated (◎)** target (starts unselected so it reads as "needs grading") · feel-flag controls (the shared `reviewControls` component: Tilt, Toxic mates, Leaver — my team, Leaver — enemy, and the three-state comms-tone switch) · **Save & next** · **Skip**. A collapsed row's own meta line ends the same way, `· <account>` (R3) — with more than one tracked account, hero/role/time alone doesn't say which one played the game, and the SR section below is labelled `◎ Skill rating · <account>` / `◎ Predicted rank · <account>` for the same reason (the ±% it records is per-account).
- **Measured (⚡) active targets are auto-graded, read-only.** Each shows its computed result for the match (e.g. "⚡ Hit — Damage/10 = 11,240"), or "⚡ no stat this match" when the match doesn't expose the stat — no manual control, contributing no entries to the saved `review.grades`. Only self-rated targets are hand-graded. A measured target with nothing to show folds into a single muted hint line instead of its own dead row (R4 — "⚡ 2 measured targets can't be graded here — this match has no stats", the names in its tooltip); a measured target that DID compute a result still gets its own row. The active-targets strip badges accordingly (R4): a measured target `auto`, a self-rated one `manual` — the same distinction the cards below it already draw.
- **"Open match ›" (R4):** the expanded card's head carries an inline link into that match's full `matchDetail` page — round score and duration ride along on the same meta line when GEP captured either (`· 3–1 · 14 min`), since the card otherwise has nothing to go on beyond map/hero/result/time/account.
- **Cross-links from Matches and the match detail page (R4):** an ungraded match's Matches row-menu (⋯) and the detail page's own head both carry a **Grade on Review** action (gated on `MatchRow.reviewed` / `MatchDetail.review == null`) navigating to `review` with `{ matchId }` — Review opens straight to that match's card (see the deep-link constraint below) instead of the newest pending one. The row menu also gained **Edit match…** (`openMatchEditorById`, fetching the detail then opening the same editor the page's own **✎ Edit match** does), and the detail page's own head gained a **Delete match** confirm beside Edit, matching the row menu's existing one.
- **Skip opens the next pending item (R2):** each inbox row is a sibling-linked entry — Skip collapses the current card and, if another pending game follows it, opens that one and scrolls it into view. A triage session stays "collapse, next card opens" without the player scrolling to find it themselves.
- **Keyboard grading (H/P/M/S/N/T/X):** while a grading card is open, `H`/`P`/`M` grade the *focused* self-rated target row and advance focus to the next; `S` saves the open review (equivalent to Save & next); `N` skips to the next pending game (R2); `T`/`X` toggle the Tilt / Toxic mates flags (R2) without opening the flags card. The first target row starts focused; the footer hint reads "keys: H P M grade · S save · N skip · T tilt · X toxic".
- **Save is undoable:** both the full card's Save & next and a collapsed row's quick-grade auto-save show a toast "Review saved — `<map>`" with an **Undo** action (~6s, hover pauses). Undo calls `bridge.clearReview(matchId)`, removing the stored review; the game returns to the inbox and the badge count.
- **Sidebar pending-count badge (R1):** backed by `DashboardData.pendingReviewsRecent` — of the unfiltered, uncapped pending set, how many landed in the **last 7 days**, minus games graded this session that fall in that same window. The lifetime total only ever grows for an active player, so it stopped answering "anything to do tonight?"; this is the number that does. Its title spells out both: "N from this week · M in total". The Review head's own subtitle states the plain uncapped total (`pendingReviews`) until the player grades something, then switches to a live session counter (R3) — "3 of 12 graded this session" — from `gradedThisSession.size` against that same total; framing the same backlog as progress once there's progress to show.
- **"Mark older as no-read" (R1):** a `viewHead` action, shown whenever the inbox is non-empty, opening a popover with an age cutoff (older than 1 day / 7 days / all of them), a live preview count (`bridge.previewPendingReviewIgnore`), and a confirm that calls `bridge.ignorePendingReviews` — saving an *empty* review (`{ grades: {}, flags: {} }`, no `Hit`/`Partial`/`Missed` claimed) on every matching row, so they leave the inbox/badge without being counted as graded. A 12s Undo toast (`bridge.clearReviews(matchIds)`) follows, same pattern as Delete match. The preview count and the actual write share one `src/core/dashboardData.ts` computation (`pendingReviewMatches` + `eligibleForNoRead`), so they can never disagree.
- **A day header's own "Mark as no-read" (R3)** is the same idea scoped to one visible day: no popover or preview needed since the header already states the count, so it goes straight to `bridge.importReviews` (an existing bulk-review write, reused here instead of `ignorePendingReviews` since the day's `matchId`s are already known client-side, not filter/age-derived) with an empty review per match, then the same `store.refresh()` + 12s Undo (`bridge.clearReviews`) toast pattern.
- **"All caught up"** positive empty state when every tracked game has a review.

## Out-of-Scope

- Editing/deleting a saved review beyond the undo-toast window (the toast's Undo is the only removal path, and it expires).
- Creating targets (the strip points to the Targets page).

## Constraints & edge cases

- **Reviews persist to the main-process store,** keyed by `matchId`, attached to the match as `GameRecord.review { at, grades, flags }` (`flags` uses the shared `MatchMental` shape the quick-log modal also writes). Path: renderer → `bridge.saveReview` → IPC → `HistoryStore.setReview`. Renderer `localStorage` is not the source of truth.
- **Skip means "later"** — the game stays pending and counted until graded.
- Saving (full card or quick-grade) re-renders locally first, then refetches via `store.refresh()` — the refetch matters because a review can also touch `primaryRank` (see the placement-confirm/offer calls below), which only exists once the save has landed. `gradedThisSession` (a renderer-side `Set<matchId>`) tracks what's been graded since the last save, so the inbox list, the subtitle and the badge all subtract it from the still-stale snapshot in the gap before the refetch resolves — the badge's subtraction is further scoped to the last 7 days, matching what `pendingReviewsRecent` itself counts.
- **Quick-grade saves a minimal review (R2):** `bridge.saveReview({ matchId, grades, flags })` only — no `performance`, `srDelta`, or placement handling, since a collapsed row never collects them. A game needing SR/performance/placement entry still has to go through **Grade**.
- **The inbox is always unfiltered.** `reviewInbox`, `pendingReviews` and `pendingReviewsRecent` are computed from the full history — narrowing the global filters never hides an ungraded game or changes the badge. `reviewInbox` is capped at 150 rows for display; `pendingReviews`/`pendingReviewsRecent` are uncapped. "Mark older as no-read" is scoped by Role/account like `reviewInbox` (via `pendingReviewMatches`), but is exempt from the Season/day-window value exactly as the inbox itself is — the whole point is clearing a backlog the date filter would otherwise hide.
- **Grades and flags feed downstream stats.** Flags OR-merge with quick-log flags into the Mental screen's composites and counts (once per game). Self-rated grades feed the corresponding target's hit-rate, hits/attempts, sparkline, and win-when-hit / win-when-missed splits — an attempt is any grade; `partial` counts as an attempt but not a hit.
- **Keyboard shortcuts are gated:** H/P/M/S/N/T/X register through the central shortcut registry with a `when` gate — they fire only while Review is the active view and the expanded card is connected, and never while a text input has focus or an overlay is open. Collapsed rows' quick-grade chips and Tilt toggle are mouse-only; the keyboard shortcuts act on whichever card is currently expanded.
- **A day group's rows genuinely aren't mounted while collapsed (R3)** — not just visually hidden — so a same-day Skip can flip the next row open in place (its host is already in the tree), but a Skip that lands in a still-collapsed day can't: it expands that day and forces a full `store.rerender()` instead, via a one-shot `forceOpenMatchId` module variable that `review()` reads once (to start exactly that match's card open, suppressing the normal "open pending[0]" default for that render) and clears immediately after. The newly-opened card schedules its own scroll-into-view on a `requestAnimationFrame`, since the host isn't attached to the document yet at the point `item()` constructs it — only once the render this call is part of has actually landed.
- **A deep-link `{ matchId }` (R4) reuses the same `forceOpenMatchId` one-shot mechanism**, but is only armed when `ctx.params.matchId` actually CHANGED since `review()`'s last call (tracked in `lastParamMatchId`) — an internal `store.rerender()` while already on this view (grading, skipping) must not keep re-forcing the same card open on every subsequent render. A `matchId` naming a match no longer in the inbox (already graded elsewhere) falls back to the ordinary "open pending[0]" default rather than opening nothing.
- **`MatchRow.reviewed` (R4)** is `g.review != null` — true even for an empty "no-read" review (`{ grades: {}, flags: {} }`), which is why it's a distinct field rather than being inferred from `targetGrades`/`flags` being present: those are absent on both a no-read match and a genuinely untouched one, and the two need to read differently on the Matches row menu and the detail head (no "Grade on Review" action offered once a no-read save exists — grading it now would contradict the point of no-read).
