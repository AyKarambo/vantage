# Screen spec: Targets (`targets`)

**Source:** `renderer/src/views/targets/index.ts`, `renderer/src/views/targets/library.ts`, `renderer/src/views/targets/libraryBrowser.ts`, `renderer/src/views/targets/builder.ts`, `renderer/src/views/targets/activeSet.ts`, `renderer/src/views/targets/detail.ts`, `renderer/src/views/targets/shared.ts` (`winSplit`, `scopeBadge`, `scopeLabel`), `renderer/src/components/reviewControls.ts` (`targetGradeRow`'s scope-badge param), `renderer/src/views/review.ts` (the scope-skip hint), `src/core/targets.ts`, `src/core/targets/templates.ts`, `src/core/targets/measured.ts`, `src/core/targets/scoring.ts`, `src/core/targets/status.ts` (`targetStatusSentence`), `src/core/targets/sampleTargets.ts`, `src/core/targets/suggestedThreshold.ts` (`suggestMeasuredThreshold`, `roundToStep`), `src/core/targets/timeline.ts` (`targetTimeline`, `OrderedAttempt`), `src/shared/contract/inputs.ts` (`ThresholdSuggestionInput`), `src/main/dataProvider.ts` (`suggestThreshold`).

**Shared context:** Renders from a `DashboardData` snapshot via `ViewContext`. The sidebar nav item uses a goal-flag icon (nav rendering owned by `screen-shell.spec.md`).

## Intent

The flexible improvement-target system: define a personal focus in the player's own words — self-rated (◎, you grade it after the game) by default, or bound to a stat and auto-graded (⚡ measured) — then track whether hitting it actually moves the winrate ("does it move your winrate?"). It works for players who never look at stats and for those who want hard numbers.

## Layout & behaviour

- **List-first once a live set exists (R5):** with any live target (or, always, on sample/demo data), the page opens on **Active focus** and **Your targets** — "does it move your winrate?", the page's actual daily question — collapsing the builder behind a **"＋ New target"** action in the view head instead of always showing a pre-filled form first. Only a real player with **zero** live targets still opens on the builder (the existing empty-state case). Clicking "＋ New target", arriving with `editTargetId`/`prefillName`, or picking a library entry's "Customize" all mount and reveal the builder; `builderManuallyOpened` (module state, mirrors `gradedThisSession` elsewhere) keeps it open through an unrelated re-render once the player has explicitly opened it.
- **Active focus panel** (above the library): quick add/remove of active targets plus **Start a fresh focus**, which is undoable (R5) — a toast ("Cleared N active targets") with an **Undo** that re-activates exactly the set that was cleared via `setTargetActive`, same reversible pattern Archive already has. Undo restamps each target's `activatedAt` (re-activating isn't "never having deactivated"), so its staleness clock restarts like any other newly-activated target. Active targets past the staleness thresholds (default 14 days OR 30 matches, configurable in Settings → Coaching) show a rotate nudge. `AuthoredTarget.activatedAt` records when a target last became active.
- **Builder card:** free-text name (starts **blank**, R5 — a real-looking placeholder example used to be one accidental Save away from a target literally named after it) · self/measured segmented control · self block (Hit/Partial/Missed grading preview) · measured block:
  - Rule = stat {Deaths, Eliminations, Assists, Damage, Healing, Mitigation, KDA} · operator {≤, ≥, =} · numeric threshold. A live preview badge reads "Hit when Deaths ≤ 4", updating on every stat/operator/value change. The threshold field is wide enough for 5 digits (per-10 damage); the scroll wheel adjusts by a per-stat step (counts ±1, KDA ±0.1, Damage/Healing/Mitigation ±250; Shift ×10), clamped at 0, with arrow-key/spinner parity.
  - **"Your usual: …" (R7):** under the rule row, a live personal-threshold suggestion — the player's own median (and a +10% stretch, and their 75th-percentile "average") for the chosen stat, over their last 30 games on the account switcher's current account (or the first known account while "All accounts" is selected), honoring the current role/hero scope. Fetched via `bridge.suggestThreshold` and re-fetched on every stat or scope change (a `reqId` guard discards a stale response overtaken by a newer request); reads "No stats yet for this stat and scope…" when nothing qualifies. **Use median** / **Use +10%** / **Use my average** buttons write the `roundToStep`-aligned value straight into the threshold field.
  - **Scope (self-rated and measured alike):** a role selector ("Any role" plus the three queue roles) and a multi-hero picker restrict grading to a role and/or one or more heroes. Collapsed by default behind a one-line summary (R5 — "Applies to: any role, any hero · Change"), since with "Any role" selected the picker paints every hero in the game; a "Change" link reveals the full picker, which starts pre-expanded when the loaded target already carries a scope.
  - **Save to library** with a "✓ Saved to your library" confirmation that reverts to unsaved on any edit. New targets are always season-scoped (no per-match scope).
- **Focus's per-entry "＋ target" quick-create** (H1) lands here with the builder pre-filled: a practice-framed name always, and — for a hero or role Focus entry — that hero/role pre-selected in the Scope picker too (a map entry only pre-fills the name; there's no map scope to set). The builder still opens in create mode (not edit), same as the Target library's own prefill.
- **Target library card** (`libraryBrowser.ts`), below "Your targets": a curated catalog grouped under four decision-timing categories (Mechanics/Macro/Strategy/Training, `TARGET_CATEGORIES`), collapsed behind a "Show the library" chip once the player has ≥3 live authored targets. A single-select filter chip row (R5 — All / Tank / DPS / Support / Measured only) narrows `TARGET_LIBRARY` by `entry.role` (a role filter also keeps 'All Roles' entries) or `entry.mode`; a category with nothing left after filtering is omitted entirely. Each entry shows its name, role/Measured badges, and its blurb always visible (never a hover tooltip); clicking the entry's main area is **Customize** (`builder.prefill`, opens the builder to review/adjust before saving — always creates, even mid-edit). A trailing **Add** (R5) saves the entry exactly as written via `bridge.saveTarget`, no detour through the builder, with a toast ("Added \"<name>\"") offering **Edit** — which refetches to find the newly-created id (`saveTarget` doesn't return one) and navigates with `editTargetId`, same path the detail page's own Edit uses. An entry already matching one of the player's own live (non-archived) targets by name shows **"✓ in your targets"** in place of Add.
  - **A measured entry's fixed threshold is personalized before Customize/Add saves it (R7):** the library ships one number for everyone ("~9k/10 is a solid DPS floor at most ranks"), so both paths first ask `bridge.suggestThreshold` for the player's own median on that stat before loading/saving the rule — the entry's OWN display role (`entry.role`) scopes that lookup (a "Tank: mitigation floor" queried unscoped would average in every Damage-role game's 0 mitigation), but the SAVED target stays exactly as unscoped as picking that entry always was; adding a role restriction here would be a second, unannounced behavior change. **Add**'s toast says so — "Added "<name>" — adjusted to your last 30 games" — only when a personal value actually existed; falls through to the fixed threshold, unremarked, otherwise. Self-rated entries are untouched.
- **Builder doubles as the edit surface:** clicking Edit on a library row loads that target's name, mode, rule, and (for measured) scope into the builder (title becomes "Edit target", sub-copy "stats keep accruing across edits"), and the footer becomes "Save changes" — updating the existing target in place (`updateTarget`), not creating a new one.
- **Library card:** per target — name, mode badge (Self-rated/Measured), a **scope badge** (R8, below) when the target carries one, one plain-language status sentence (`targetStatusSentence`, below), sparkline, hit-rate (or "New" at 0 attempts), hits/attempts, a signed **lift chip** (R6 — `winWhenHit − winWhenMissed`, e.g. "+18 pts when hit"; green ≥ +5pts, red ≤ −5pts, muted between; tooltip states both raw rates, "62% when hit · 44% when missed"), shown only once **both** sides have at least one decided game, and a lifecycle action row: an **Active** chip ("◎ Active on Review" / "Inactive") toggling whether the target is graded on Review, **Edit**, **Archive**, and **Delete**. Win-when-hit/win-when-missed themselves (the bars, on the detail page) live there, not on the row.
- **Scope badge (R8, `views/targets/shared.ts`'s `scopeBadge`/`scopeLabel`):** a role icon plus its scope in words — "Tank", "Zarya, D.Va" (hero-only), "Support · Ana" (both) — `null`/absent when unscoped (the common case). Shared by the library row (after the mode badge), the detail header (after the mode badge, before the phase chip), and Review's grade row (`targetGradeRow`'s optional 4th param — threaded in from `views/review.ts`, since `reviewControls.ts` is a `components/` module and stays decoupled from `views/targets/`) — a player can tell WHY a scoped target didn't show up on a given match without opening the builder.
- **Target detail page** (`detail.ts`, a row's "Details ›"): name, rule, mode/scope/phase badges, sparkline, hit-rate, then the two win-split bars (`winSplit`) — win-when-hit and when-missed. Each bar states its own sample size alongside the rate (R6 — "62% · 12 games"), or, when that side has zero decided games, an empty track reading "— · no games yet" instead of drawing a bar for the player's baseline as if it were measured — a one-line sub underneath ("Your winrate in games where you hit this target vs games where you didn't") names what the two bars compare. Below that, a **"Recent attempts" card (R8)** — absent when the target has none — lists its last 10 attempts (`TargetSummary.recentAttempts`, newest first): relative date · map · result pill · grade pill (the `GRADES` tones `reviewControls.ts` already defines, so a grade reads the same color everywhere) · the measured per-10/KDA value when the mode has one; each row opens that match (`matchDetail`, `{ matchId }`) — the natural post-session question, "which games did I miss it on, and did I lose those?", used to have no answer even though the per-game series already existed. Then the Focus Trend panel (live targets only) or a **mode-aware fallback hint (R8)** — "Demo targets don't carry a focus trend — build your own to see it" for `ctx.data.isSample`, "Archived targets stop tracking their trend; restore it to resume" for an archived target, or the original "No focus trend yet…" only for a genuinely fresh live one (the three used to share one "not live and tracking yet" sentence, which was wrong for the first two) — then the same lifecycle actions as the list row.
- **Archived section** below the live rows (when any exist), `Archived (N)`, each row with its name, rule, a **Restore** button, and a **Delete** button — deliberately without `targetStatusSentence`: an archived target has nothing left to act on, so the compact form skips the verdict a live row's row shows.
- **Delete** (live or archived) opens a confirmation modal ("Delete "<name>"?") warning that removal is permanent, that stats stop counting, that grades already saved on match reviews stay stored but inert, and suggesting Archive instead; confirming calls `deleteTarget`.

## Grading

- **Measured (⚡) targets auto-grade from stats,** read-only — no human read. A measured target's grade is computed per match from its bound stat: Damage/Healing/Mitigation/Eliminations/Assists/Deaths as **per-10-minutes-played** rates (played time from `src/core/playedTime.ts`; a hero-scoped target divides by that hero's played minutes), KDA as the match ratio, against the rule's operator/threshold with a 10% partial band. Its **scope** (role and/or hero) restricts which matches it evaluates. Matches missing the stat are skipped (not attempts). Scoring lives in `src/core/targets/measured.ts` + `scoring.ts`; stored `review.grades` for a measured target are ignored (no double-count).
- **Self-rated (◎) targets are hand-graded on Review** (and optionally in the log-match modal); keyboard grading cycles the self-rated rows only. (See `screen-review.spec.md`.)

## Out-of-Scope

- Grading self-rated targets here (done on Review / in the log-match modal).
- Editing or deleting rows in the demo sample library.

## Constraints & edge cases

- Measured rules serialize as `"<stat> <op> <value>"`; self-rated as `"You grade it"`.
- With **no** authored targets (archived ones counted), the library shows a **synthetic sample**: 4 seeded targets whose hit-rates/sparklines are generated deterministically around the player's real baseline winrate. The sample only reappears once the authored library (live + archived) is truly empty.
- A freshly authored target starts at 0 attempts with both win-splits at the player's baseline (`hitDecided`/`missDecided` both 0 — the renderer never shows this baseline as a measured bar, see above); once grades exist (Review for self-rated, auto for measured) its hit-rate = hits/attempts (partial counts as an attempt but not a hit), the sparkline shows the last 8 attempts, and win-when-hit / win-when-missed reflect the winrate of the DECIDED (Win/Loss) games graded hit vs. not-hit — a side still falls back to the baseline while it has zero decided games of its own, `hitDecided`/`missDecided` (R6) being what tells the renderer that number isn't measured. `TargetSeed`-based sample/demo targets synthesize `hitDecided`/`missDecided` too (no draws in that model, so every attempt decides), so the lift chip and status sentence read the same on demo data as on a real target.
- **Status sentence lift/habit verdict (R6, `targetStatusSentence`):** when no learning-phase verdict applies (archived targets, and the demo/sample library, which never carries a `learning` curve) — first, "essentially automatic": `attempts >= 20` and `hitRate >= 80%` reads **"Habit is set — N% hit over M games, rotate it out"**, ahead of any lift read (the missed side rarely has enough games left to say anything trustworthy about lift by then). Otherwise, once BOTH `hitDecided` and `missDecided` are `>= 8`, the **lift** (`winWhenHit − winWhenMissed`) drives the sentence — `>= +5pts` reads **"Worth keeping — +N pts when you hit it (M games)"**, else **"No effect yet — hitting it hasn't moved your winrate; consider swapping it"** (never a fabricated number). Below that 8-decided-games-per-side floor, the older plain hit-rate bands (≥60% / ≥35% / below) are still the fallback — a small sample doesn't get a lift claim it can't back up.
- Authored targets sort newest-first and fully replace the sample library once any exist.
- **Active-target selection is explicit and user-owned** (shared with `screen-review.spec.md`): a target's `isActive` flag (default `true` on creation) determines whether it appears in the Review grading strip.
- **Edit accrues, it doesn't reset:** editing name/mode/rule keeps accrued grades (a rule change mixes old- and new-rule attempts — a grade is tagged to the target id, not the rule text).
- **Archive is the primary removal action** and is **undoable** (immediate, no confirmation, `Archived "<name>"` toast with Undo ~6s): an archived target leaves the live library and the Review active set but retains its history and is restorable. **Permanent Delete** is confirmation-gated; grades stored in past reviews are untouched but become inert once the target is gone.
- Lifecycle actions no-op on sample-library rows (there is nothing to persist against).
- **Templates:** see the Target library card above (`TARGET_LIBRARY`, `src/core/targets/templates.ts`) — this superseded the earlier flat "Start from a template" chip row.
- **`suggestMeasuredThreshold` (R7)** reuses `matchStatValue` — the exact evaluator a measured target is graded with — over one account's last 30 games BY RECENCY (not the last 30 games that happened to measure; a role/hero-scoped stat with sparse coverage can legitimately return very few or zero qualifying games even with plenty of history overall, which reads as "no stats yet" rather than reaching arbitrarily far back to force a sample), filtered to the given role/hero scope, then median + 75th-percentile (linear interpolation) over whichever of those actually measured. Pure and Electron-free, run over UNFILTERED history like the readiness baselines — a smurf's easy-lobby numbers never inflate the main account's suggestion, since it's always scoped to one explicit account. `null` when nothing qualifies at all.
- **`recentAttempts` (R8)** is derived from the SAME already-scoped/graded games `attempts`/`hits`/the win-splits count — not a second, independently-filtered pass — so it can never disagree with the row's own numbers about which games attempted this target. `OrderedAttempt` (`timeline.ts`) carries `matchId`/`map` for exactly this; the sample/demo library synthesizes `recentAttempts` from REAL recent games (real matchId/map, a deterministic seeded-hash grade) rather than a wholly fabricated list, so a demo "Recent attempts" row still opens a match that actually exists.
- **The head says "Targets" (R8),** matching the nav item, the back-stack label and the list card's own title — it used to read "Improvement Target" (singular), the one place on the screen that disagreed.
