# Screen spec: Settings (`settings`)

**Source:** `renderer/src/views/settings/**` (`index.ts` — the section rail (W1), `general.ts`, `accounts.ts`, `appBehavior.ts`, `diagnostics.ts`, `dataLocation.ts`, `importCard.ts`, `masterData/**`), `renderer/src/components/breakReminderEditor.ts`, `readinessSettingsEditor.ts`, `stalenessEditor.ts`, `sessionSettingsEditor.ts`, `gradingSettingsEditor.ts`, `logLevelToggle.ts`, `renderer/src/components/inlineLink.ts` (W1 — the shared "See it on X →" jump, also used by `views/about.ts`, `views/faq.ts`, `views/overview.ts`), `renderer/src/store.ts` (`SettingsSection`, `ViewParams.section`), `src/core/rankDisplay.ts` (`rankParts`), `src/main/config/appConfig.ts` (`MasterDataConfig.lastCheckedAt`, W1).

**Shared context:** Sidebar entry under the **App** group. The break-reminder / readiness / session state reads from a `DashboardData` snapshot via `ViewContext`; the accounts, app-behavior, data-location, and master-data cards fetch async from the bridge. Not affected by the global filter bar.

## Intent

The canonical home for everything that configures the app: account management, coaching nudges, window behavior, appearance, diagnostics, data storage, and the Overwatch master-data (heroes/maps/seasons) editor — one sidebar place instead of settings scattered across screens.

## Structure

Two tabs so neither is a single long scroll: **General** and **Master Data**. Re-entering Settings always starts on General.

- **Section rail (W1):** a row of jump links — Accounts · Quick Log · Coaching · App behavior · Appearance · Diagnostics · Data storage · Import — right under the view head, always rendered but only visible while on General. Clicking one switches to General (if needed) and scrolls/flashes that card into view, mirroring Maps' `highlight` cross-link idiom but keyed by a stable `data-settings-section` attribute rather than text matching. `ViewParams.section` (a `SettingsSection`, classified `'effect'` in `backStack.ts`) drives the same reveal on arrival — About's "Data storage location →" and the FAQ's "See the exact folder in Settings →" both now land pre-scrolled to the Data storage card instead of the plain top-of-page open they used to.

## General tab

- **Accounts card** — create / edit / delete the accounts you log matches against (a `battleTag → label` mapping). It is a **list**, not a control panel: one aligned grid row per account (name + sub-line · games · a compact per-role rank summary · actions), with a header row; everything rank- and placement-related lives behind the row's **Manage ranks…** button. It lists **every account it knows about**, each with a game count:
  - **Row order (W2):** the account readiness treats as the **main** sorts first, then every other account by games descending, with the **Unknown** bucket always last — never alphabetical or insertion order. The main account (from `ReadinessSummary.mainAccount`, read off the same `DashboardData` snapshot every other card on this view uses) wears a small **main** pill after its name (title: "Readiness treats this as your main — most played, recently active. Games on other accounts move that read less."); no account wears one when readiness has no clear main yet. The card's own subtitle states the same fact in words once a main exists.
  - **Configured** accounts (sub-line: the BattleTag): **Edit** (rename the BattleTag / display name, inline, spanning the row) and **Forget name** (non-destructive — drops the label mapping, leaves the matches; named for what it does rather than reading like the destructive action below it, W2).
  - **Detected but unlabelled** raw-tag accounts (sub-line: *detected, unlabelled*): **Label** (assign a display name; the BattleTag is fixed, and the account's history rows adopt the label) and **Delete…**.
  - The **Unknown** bucket (sub-line: *no captured BattleTag*): **Delete…** only (there is no tag to label against).
  - The game count is its own right-aligned column, not part of any sub-line.
  - **Delete…** on a detected/Unknown account is **irreversible, behind a confirm**, and rendered in the danger variant (W2 — it used to look identical to the non-destructive "Forget name"/"Edit" ghost buttons beside it) — it permanently removes that account's matches *and* its rank anchors, and afterward reconciles the dashboard's account filter back to "All accounts" if it pointed at the deleted one.
  - The per-role **summary chips** come from `accountRoleSummary` (`renderer/src/roleStatus.ts`), a deliberately terser sibling of `roleStatus` over the same `rankParts`: short role tags (`Tank`/`Dmg`/`Sup`/`OQ`) and short tier codes (`shortRankLabelOf` in `src/core/rankDisplay.ts` — `B S G P E D M GM C` glued to the division) so a row never wraps — `Dmg · GM4 · 16%` (🛡 when protected), `Sup · Placements 3/10`, or `Tank · Placements 10/10 · confirm rank`. A run's predicted rank is dropped here; the full text is one click away in the modal. Only roles the account actually tracks appear. An account tracking **no** role shows a **Set rank…** jump-link (W2, replacing an inert "No rank yet" span) straight into the **Set rank** dialog — Cancel or Save both return to the **Manage ranks…** modal rather than leaving the bare list.
  - **Manage ranks…** opens the **Ranks & placements** modal for that account: all four roles as aligned rows (role · status pill · that state's actions — start placements now or from an earlier match, change the start match, reset to begin / cancel the run behind the two-click confirm, finish early / confirm the revealed rank, recount a drifted run), plus **Set rank…** to set/replace a role's one-time anchor (set once; logged competitive matches move it from there; editing re-anchors from the entered value; a negative % is a rank-protection buffer). The modal re-reads ranks + placements and repaints after every write, and reloads the card + dashboard snapshot so the sidebar chip and Overview KPI follow. Overlays never stack: a sub-dialog (Set rank, the match picker, the reveal-rank confirmation) closes the modal first and reopens it when done — on Save, Cancel, Escape or a backdrop click alike.
  - **App-wide:** when a competitive match logs on a *different configured account* than the one currently selected, the app auto-switches the account filter to it. A hand-logged match that triggers the switch (L3) shows a short "Now showing `<account>`" toast — a live-tracked switch stays silent, since it lands while the player is still in Overwatch, not looking at Vantage.
  - The sidebar's **account switcher** popover (`shell.ts`) lists accounts **most-recently-played first** (W2, `DashboardData.accountActivity` — unfiltered by the active Role filter, so a role filter can't hide that an account was just played on a different role tonight), and each row carries a muted **"N games · last played Xd"** line under the name (games from the same filtered `byAccount` split Trends uses; last-played from `accountActivity`, relative via the shared `relTime`).
- **Coaching card** (W1 — `sub: 'nudges and thresholds used across the app'`) — six labelled blocks (`.coaching-block`, a `field-label` heading + a one-line hint naming what it actually affects + the control + a "See it on X →" jump via the shared `inlineLink`, separated by a hairline rule), in order:
  - **Quick Log** (folded in as the first block, W1 — used to be its own standalone full-width card) — how many "most-played" heroes the Log Match hero picker shortlists before falling back to search (3–15). No jump link: it affects the Log Match modal, not a screen `ctx.navigate` can land on.
  - **Break reminder** — on/off + threshold (mechanism owned by `screen-mental.spec.md`). Jumps to Mental.
  - **Readiness coach** — enable + launch-toast (owned by the readiness specs). Jumps to Readiness.
  - **Target rotation** — the staleness thresholds `screen-targets.spec.md`'s rotate nudge uses. Jumps to Targets.
  - **Current session** — the gap-threshold preset (30m–6h) governing the sidebar's Current session card, the Overview last-session debrief, and Matches' "By sitting" grouping (S4); readiness's own fatigue-curve tuning is separate. Jumps to Matches.
  - **Grading margin** — the measured-target partial-credit margin (`gradingSettingsEditor`). Jumps to Review.
- **App behavior card** (loaded async via `getAppSettings`, persisted in main-process config as `AppUiSettings`): **Close-to-tray** (✕ keeps Vantage in the tray vs quits), **Run at login** (starts hidden in the tray at Windows login), and **Demo data** (preload a sample season; no visible effect once real history exists). Toggles apply instantly and flip in place (no toast). While **MCP endpoint** is on, the card also shows the resolved absolute bridge path (`AppInfo.mcpBridgePath`, W4 — `<install dir>/resources/mcp/stdio.js` packaged, `dist/mcp/stdio.js` in dev) in mono, plus a **Copy Claude Desktop config** button that writes the `mcpServers` JSON block (`src/core/mcpConfig.ts`, pure) straight to the clipboard — replacing the old "go find the path in the README and type the JSON yourself" flow.
- **Appearance card** — a **Winrate colours** segmented control (default teal–rose vs a colorblind-safe blue–orange palette). The choice swaps the win/loss/draw encoding across every chart and screen without a restart, persisted as a renderer pref and applied at bundle load.
- **Diagnostics card** — the log-level toggle (`info`/`debug`, session-scoped), **Open log viewer** → the Logs screen (`screen-logs.spec.md`), the session's error/warning counter (W5, plain text when clean; an accent pill once errors exist, clicking it opens Logs preset to the `error` filter), and **About Vantage →** the About screen (version/build/support live there).
- **Data storage card** — where *all* Vantage data files live (`history.db`, `manual.json`, `outbox.json`, `rankAnchors.json`, plus a legacy `history.json` backup when present). **Change…** migrates everything with a copy-verify-then-delete guarantee (originals removed only after the switch commits); a target folder that already holds Vantage data is offered as **adopt-or-cancel**, never overwritten. Details in `sqlite-storage-notion-sync.spec.md`.
- **Import card** — bring match history in from a Vantage import JSON (e.g. the Obsidian→Vantage script); imported matches are marked so "Remove imported matches" clears exactly that set.

## Master Data tab

The Overwatch master-data editor — add / edit / remove heroes (name + role), maps (name + game mode + competitive-pool `isActive`), and seasons (start + label), plus the single **Update** action that fetches the latest heroes & maps and previews additions/changes for per-item accept. Full behavior in `editable-master-data.spec.md`.

- **"Last checked" line (W1):** under the card head — "Last checked `<relTime>`" (or "Never checked"), then "· OverFast API (community mirror of Blizzard data) · nothing about you is sent", naming the source and what leaves the device for the first time. `MasterDataConfig.lastCheckedAt` (`config.local.json`, main-process) is stamped on every successful `masterDataFetchUpdate`, regardless of whether it found anything new — "is this source still being read", not "did it find changes" — read into the renderer via `bridge.getMasterDataCheck()` on mount and again right after a manual check. Past 60 days (or never checked) it carries an accent pill, **"A new hero or map may be missing — check now."**

## Out-of-Scope

- Notion token / database management (own screen — `screen-notion.spec.md`).
- App version / build facts / support contact (the About screen — `about-page.spec.md`).
- Editing window bounds — size/position/maximized state persist automatically in the main process and never cross the bridge.

## Constraints

- App-behavior and data-location settings live in main-process config (`config.local.json`), not renderer localStorage — they must apply before the renderer exists (window restore, tray-first launch). The winrate-colour choice is a renderer pref.
- Reversible settings apply immediately; only irreversible actions (account data deletion) sit behind a confirm modal.
- The debug log-level toggle is session-scoped: it resets to `info` on app restart.
- Rank display everywhere composes the shared `rankParts` renderer so protection and progress read identically across surfaces.
