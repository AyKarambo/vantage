# Screen spec: Overview (`overview`)

**Source:** `renderer/src/views/overview.ts` (incl. `firstWeekUnlockCard`, F2; `checkInStrip`, S10 phase 2), `renderer/src/coachHeadline.ts` (`coachHeadline`), `renderer/src/app/shell.ts` (`announceDemoRetired`, F2), `src/core/demoPreference.ts` (`demoTransition`, F2), `src/core/analytics/session.ts` (`sessionDebrief`), `src/core/rankDisplay.ts` (`rankParts`), `renderer/src/components/checkInPrompt.ts` (S10 phase 2, shared with the idle Live screen — see `screen-mental.spec.md`).

**Shared context:** Renders from a `DashboardData` snapshot via `ViewContext` (`renderer/src/views/view.ts`); the global filter bar (Role · Season) and the sidebar account switcher re-scope it. The demo dataset shows a "Demo data" badge. `Ctrl+K` opens the command palette (see `screen-shell.spec.md`); the quick-log modal opens from this screen's **Log match** CTA or the palette's Log match action.

## Intent

The landing screen — "priority maps at a glance". Answers in one glance: *how am I doing* (KPIs) and *where are the points hiding* (which maps bleed rank), so the player knows what to fix before queueing.

## Layout & behaviour

- **Greeting header:** time-of-day greeting + player name, a computed coach headline (O1), and the primary **Log match** CTA (opens the quick-log modal).
- **Pre-session check-in strip (S10 phase 2):** right below the header, "How are you feeling right now?" plus **Calm** / **Edgy** / **Tilted** — the same `checkInPrompt` component the idle Live screen's "Before you queue" card offers (see `screen-mental.spec.md` for the full mechanism, the `tiltByCheckIn` read it feeds, and the demo-data hide rule). Hidden while a match is in progress (`getLiveMatch()?.live` — nothing to check in for) in addition to the component's own demo-data hide.
- **"Next up" strip (O3):** below the header, a row of pill buttons naming whatever needs the player's attention, highest urgency first — "`<N>` matches need a result" (competitive games GEP delivered with no win/loss, `pendingMatches`), "`<N>` games to review" (`pendingReviews`, the full unfiltered backlog, not just the sidebar badge's last-7-days count), and "Confirm your rank" when any tracked placement run is `awaitingRank` (opens the same reveal-rank dialog the Rank KPI's own CTA does). Each pill opens Review, except "Confirm your rank" which opens the placement-complete dialog directly. Hidden entirely with nothing pending.
- **Coach headline (O1):** the date, then the single strongest computed read available, in a fixed priority order — the first candidate that clears its own sample gate wins; the app deliberately doesn't try to score dissimilar signals (a rank swing, a net-loss tally, a fade point) against each other on one scale. In order: (1) **rank movement** — the anchored Rank KPI's own anchor→now swing, once it clears the same ±10-point neutral band the KPI's arrow uses, attributed to whichever role clearly carried or dragged it (≥8 games, a ≥3-game W/L split) when one stands out; (2) a **role deficit** — the worst `role`-dimension Focus entry with ≥30 games, "`<Role>` is costing you N net losses over M games this range"; (3) **session fade** — the same late-sitting winrate drop Trends' extremes read from (`sessionFade`), "You drop to N% from game G on — ending sessions earlier is free rank." With no signal clearing its gate: "No strong signal yet — keep logging." Whichever signal wins carries a **"Why →"** link (rank movement and session fade open Trends; a role deficit opens Focus) — inert only on the fallback line, which has nothing to point to.
- **"A few things unlock as you play" card** (F2; glow variant, above the last-session debrief): shown once the demo season has actually **retired** — `shell.ts`'s `demoTransition('demo-retired')`, firing the moment history gains its first real game while demo was showing, also fires a toast ("Your first tracked game is in — the demo season retired. Everything from here is yours.", action: **View Overview**) and resets the card's dismissed pref so it reappears if demo genuinely comes back and retires again (deleting your only real game restores it). Lists the three sample-size floors that gate other screens — reading the SAME core constants those screens gate on (`MAP_MIN_GAMES`, `COST_MIN_SAMPLE`, `READINESS_TUNING.minGames`/`.minSpanDays`), so the copy can never drift out of sync with what actually unlocks: "3 games on a map — Focus starts ranking it", "5 flagged games — Mental shows what tilt and comms actually cost you", "15 games over 14 days — Readiness starts reading your form". A **Got it** button dismisses it (`prefs.firstRealGameBannerDismissed`); it also auto-hides once total real games reach the highest floor (15) even without an explicit dismiss, and never shows at all while `isSample` or with zero real games.
- **Last-session debrief card** (S3; "Last session · `<weekday>` `<day-part>` · N games", glow variant, above the KPI row): shown once the trailing gap-based sitting has **closed** (a still-open one is the sidebar's live "Current session" card instead — showing both would double up the same numbers). Sub-line: `W–L` · "toughest: `<worst map>`" (when known) · "tilt flagged ×N" (when any). 2–4 stat boxes, only the ones with data: `W–L` (tinted by net) with signed net, winrate, then whichever of SR change / best map / targets-hit rate are present. Below the boxes, **"Review these N games →"** (opens Review; shown only when the sitting has ungraded competitive matches) and **"View games →"** (opens Matches scoped to the sitting's start day, `{ day }`). A ✕ **collapses** the card to a one-line "`<title>` — `W–L`. Show again" sub instead of removing it outright, keyed by the sitting's `endedAt` (`recapShown` pref) — clicking the collapsed line re-expands it, and a new sitting closing always starts expanded again.
- **KPI row:** **Winrate** (with a recent-form delta chip), **Games** (W·L split, plus a `·N D` draws segment when the range has any — `WinLoss.draws` used to be silently dropped here), **Rank**, **Streak** (accented). Its secondary line (C7) is context-aware, not a fixed "ride it"/"reset it" pair: a win streak still reads "ride it"; a loss streak only reads "reset it" once it reaches the real break-reminder threshold (`breakReminder.afterLosses`, or 3 when the reminder is off) — a single loss no longer reads as an urgent nudge. Below that threshold (or with no streak at all), it falls back to something actually informative: the current sitting's `W–L` tally when one is open, else "last game `<relTime>`" — with the active role name appended when a role filter is set. The card's hover tooltip states the range's extremes (`DashboardData.extremes`, `streakStats`) — "Best W`<n>` · worst L`<n>` in range" — real context that doesn't need to fight the actionable cue for space.
  - **Every KPI tile drills down (O4)**, wired via a new `KpiOpts.onClick` (never combined with an existing `action` CTA button — nesting a button inside the whole-card button that produces would be invalid HTML): **Winrate** → Trends, **Games** → Matches, **Streak** → Matches. **Rank** opens the Manage-ranks modal (scoped to the already-known anchored account) when it's showing an anchored rank with no open placement run, or Settings → Accounts when showing "Placements N/10" for a run that isn't yet awaiting confirmation or when several tracks are placing at once with nothing to disambiguate; the two branches that already carry their own CTA button ("Set rank" on the winrate-heuristic fallback, "Confirm rank" once a run is `awaitingRank`) are left as they are.
  - The **Rank** KPI shows the greeting account's **real anchored rank** — the calculated rank of its most-played anchored role (`DashboardData.primaryRank`) — composed through the shared rank renderer (`rankParts`): the tier/division label, a 🛡 protection shield and buffer text when the rank is protected, else the within-division progress %. Overview is the **only** surface that shows the anchor→now **movement arrow** (▴ rising / ▾ falling / neutral-flat, from the shared `rankParts` `movement`), and the arrow is truthful (neutral within ±10 ladder points). Outside the neutral band the delta also states the **magnitude** (C1) — `▴ +38% since anchor · 16% in division` — since `primaryRank.movement` was already computed and threaded through, but used to be reduced to a bare arrow next to the unrelated in-division buffer %, so "how much" never actually appeared anywhere; the neutral band omits the number (nothing meaningful moved). When the greeting account has no rank anchor (and isn't mid-placements — that case gets its own KPI shape), the tile falls back to the winrate-derived heuristic (`progression`) — value **"`<tier><division>` est."** (C4, e.g. `E3 est.`, the `est.` marking it a guess rather than ground truth), delta **"from winrate — no rank set"** with no movement arrow (that stays anchored-branch-only), and a **"Set rank"** action opening the same Manage-ranks modal Settings uses (`openManageRanks`, exported from `settings/accounts.ts`), scoped to the active account filter or the first tracked account.
  - The **Winrate** KPI's delta (C4) states its own window honestly — `▾ 16 pts · last 5 days` (or `weeks`, following `DashboardData.trend`'s own day/week bucketing) — instead of a bare, unitless "recent"; a hover tooltip spells out "Mean winrate of your last 5 days/weeks vs the range average". Below that, the **Winrate** and **Games** KPIs each carry a second, unaccented line (C3, `DashboardData.previous`) comparing the whole active window against the one immediately before it — `vs 2026 Season 3: +3.2 pts` on Winrate, `vs the previous 30 days: +12 games` on Games — a period-over-period read distinct from the smoothed within-range delta above it. Absent on "All time" (there's nothing before everything) or when the active season has no earlier entry with data; the Winrate sub is further gated on both windows having at least one decided game (nothing to compare a rate against otherwise).
- **Role strip (O4):** a single wrapping line of chips under the KPI row — an **All** chip plus one per role in `DashboardData.options.roles`, labelled `<role> <winrate>% · <games>g` when that role appears in the (already filter-scoped) `byRole`, or just the plain role name otherwise. Each click sets the Role filter (`ctx.setFilter({ role })`); the chip matching the active filter renders "on". Hidden with fewer than 2 roles — nothing to compare.
- **Maps scatter card:** winrate × volume for every map in range; dot colour encodes the **game mode** (O2 — 7 stable hues; a per-map colour couldn't stay distinct once the pool passed ~11 maps), and the legend shows one swatch per mode present (at most 7), sorted by games, not one per map. A **focus dot** (net ≥ 3) carries an always-visible short-name label beside it, anchored away from whichever plot edge it's nearest — the bottom-right dots the card copy says to "fix first" no longer need a hover to identify. The X axis gets three numeric ticks (`0` / half / max games) with faint gridlines alongside its "fewer ↔ more games" caption. The full map name is still on hover/focus (both the dot and, historically, the legend). Clicking a dot opens that map's own games on Matches (`{ map }`, H3).
  - **True first-run replacement (F4):** with no games at all in history (`d.overall.games === 0 && d.totalGamesAllTime === 0`), this whole card is replaced by a first-run card instead — "No games tracked yet — Vantage records ranked games automatically while Overwatch is open, or log one by hand", **Log match** and **Turn on demo data** (`setAppSettings({ demoPreference: 'on' })` then `store.refresh()`, same round-trip the first-run prompt and Settings → App behavior use).
- **Top priority callouts:** the top 3 net-losing maps (net = losses − wins > 0, from `focusMaps`) with games, signed net, and winrate; hint copy uses practice/review framing; each row is a real clickable control (keyboard-reachable, hover/focus-visible styled) straight into that map's games on Matches (`{ map }`, H3). A map the master-data catalog marks out of the current competitive pool carries an **"Out of pool"** tag next to its name (H1, cross-referenced from `masterData.maps` directly — this callout reads `focusMaps`, not the richer `FocusEntry` shape `screen-focus.spec.md` describes, so it tags pool status itself rather than sharing the field). Each row also carries Focus's own **"Track as target"** quick-create (O4, `practiceTargetButton`, shared with `screen-focus.spec.md`'s rows so both stay on the same prefilled name/confirm-popover behaviour) — clicking it stops the row's own navigation from also firing. When the list is empty, the panel shows either the F1 unlock hint or the clean-season celebration, gated on `qualifiedMaps` (F4, see Constraints below) — and the "These are dragging your season…" practice hint below it is hidden entirely either way, since nothing is actually dragging anything. The CTA **"Open Focus →"** is the Overview's single entry to the Focus screen (Overview teases, Focus is the hub — hierarchy owned by `screen-focus.spec.md`).
- **Bottom row (five cards, wrapping):** **Activity** (leftmost, always present), **Mental** snapshot (Calm/Tilted bars + a truthful break-reminder line reflecting the real per-user setting), the **Readiness** teaser (only when the feature is enabled), **Active targets** and **Heroes** (O3, both below). Activity renders regardless of the Readiness toggle. At ≤1300px width the row becomes a 2-column grid so five cards stay readable instead of squeezing edge to edge.
- **Activity calendar heatmap:** games per day, cell colour = winrate, opacity = game count. The window follows the active filter now (O5, `activityWindowDays`) instead of a fixed 35 — 35 days for a ≤30-day range (a shorter grid would feel cramped even with cells empty), the real elapsed span for a longer numeric range or a season (floored at 35, capped at 13 weeks/91 days either way — a one-third-width card can't usefully show more), 91 for "All time"; the card's own subtitle states the real span ("last 91 days"). A weekday column (Mon/Wed/Fri, every other row so the 13px cells stay legible) sits left of the grid, and a month label sits above the first column of each new month — both computed by parsing the `YYYY-MM-DD` date key's own digits into a plain `new Date(y, m-1, d)` rather than reinterpreting the UTC-midnight string through the viewer's local offset (the old `new Date(string).getDay()` landed a day off for anyone west of UTC). The legend (Losing/Even/Winning swatches, plus a "1 · 3 · 6+ games (opacity)" note explaining what the opacity axis means) stacks vertically beside the grid; a bottom hint line reads "games/day · colour = winrate · click a day to open its matches". Clicking a day cell with games navigates to Matches filtered to that day.
- **Active targets card (O3):** one row per active, non-archived target — name, a hit-rate sparkline, the hit-rate %, and a **stale** tag when the target is overdue for rotation (the same `isStale` check the Targets active-set panel already gates its own nudge on). Clicking a row opens that target's detail page. Empty state: "No active target — pick one from the library → Targets".
- **Heroes card (O3):** the top 5 heroes by games this range, each a winrate bar labelled `<hero>` with `<winrate>% · <games>g`. Clicking one opens Heroes with that hero's row highlighted (same cross-link pattern the Maps mode cards use, scoped to just the highlighted hero so it always lands even below the persisted min-games floor).

## Out-of-Scope

- A KPI's own value never opens anything beyond what O4 wires (Winrate → Trends, Games/Streak → Matches, Rank → Manage-ranks or Settings → Accounts) — no per-metric drill-down deeper than that single destination.
- Any practice-queue feature or copy — no queue feature exists (GEP-only guardrail); no "queue" verb in the copy.
- The cross-dimension focus list itself (owned by `screen-focus.spec.md`).
- The break-reminder mechanism itself (owned by `screen-mental.spec.md`).
- The coach headline's candidate signals stop at three (rank movement, role deficit, session
  fade) — a worsening tilt trend and a "best time to queue" read are plausible future signals
  but aren't wired in, and a net-losing **map** doesn't feed the headline (only role deficits
  do; a map's own "fix this" read stays on the Top priority callout below, which already covers
  it via its own click-through).

## Constraints & edge cases

- Recent-form delta = mean winrate of the last ≤5 trend buckets minus the range baseline, in points; suppressed below 3 buckets (deliberately smoothed).
- The scatter flags a map as focus-worthy at net ≥ 3; maps sort most-played-first so legend order and per-map colours stay stable.
- The Winrate KPI shows "–" at 0 games.
- The recap is computed in pure core (`sessionDebrief`, `src/core/analytics/session.ts`, unit-tested) over the **unfiltered** history, same account scope as `session` (a real sitting doesn't span accounts) — delivered as `DashboardData.recap`, absent when there are no games at all. Best/worst map are only set when the sitting had ≥2 distinct maps; the targets-hit rate only when at least one target was graded — folding in self-rated review grades AND every currently-active **measured** target's fresh auto-grade (a stale stored grade, or one from a target that's since gone inactive, can't leak in); SR change only when at least one game in the sitting logged a `srDelta`.
- With no net-losing maps AND `qualifiedMaps ≥ 1`, the Top priority callout shows "No net-losing maps — clean season. 🎯"; with `qualifiedMaps === 0` it shows the F1 unlock hint instead — a first-week player hasn't earned the celebration yet (F4). The practice hint below the callout ("These are dragging your season…") is hidden whenever the callout list is empty, either way.
- With no games at all in history (`d.overall.games === 0 && d.totalGamesAllTime === 0` — a fresh install, or demo data declined), the scatter card is replaced entirely by a first-run card: "No games tracked yet — Vantage records ranked games automatically while Overwatch is open, or log one by hand", with **Log match** and **Turn on demo data** actions (the latter round-trips `setAppSettings({ demoPreference: 'on' })` then refreshes, same as the first-run prompt and Settings → App behavior) (F4).
