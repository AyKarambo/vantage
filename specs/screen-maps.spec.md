# Screen spec: Maps (`maps`)

**Source:** `renderer/src/views/maps.ts`, `renderer/src/components/chartCard.ts` (`extraActions`, H4), `renderer/src/charts/plots/bars.ts` (`horizontalBars`'s `meta` slot, H4; `dimmed` row option, F4), `renderer/src/charts/tooltip.ts`, `renderer/src/components/trendArrow.ts`, `renderer/src/components/clickableRow.ts`, `src/core/maps.ts`, `src/core/masterData` (`makeMapMode`, `makeMapActive`, H4), `src/core/analytics/focus.ts` (`MAP_MIN_GAMES`, shared with Focus's own map floor, F1), `renderer/src/prefs.ts` (`minMapGames`, `mapModeFilter`, H4).

**Shared context:** Renders from a `DashboardData` snapshot via `ViewContext`; the global filter bar re-scopes everything shown. Accepts a `highlight` param (`ViewParams.highlight`) — the entry point for the command palette's Map results and the map cross-links on Matches rows, the Overview scatter, Focus's map rows, the Heroes drawer's By-map rows, and Live's priority card (see `screen-shell.spec.md`, `screen-matches.spec.md`).

## Intent

"Where the games actually go" — performance by game mode, play-share per map, and every map ranked best → worst, so the player sees which modes and maps carry or drain their results. The mode cards and the ranking used to sit adjacent but unconnected (H4): a card wasn't clickable, and the ranking carried no mode column even though the renderer already resolves map → mode everywhere else.

## Layout & behaviour

- **One card per game mode** (`byMapType`): mode name, winrate (colour-coded), games count, signed net, winrate stat bar, and — when the mode has any map data — a one-line **"Best `<map>` · Worst `<map>`"** meta line (or **"Only map so far: `<map>`"** when the mode has exactly one), scoped over the same floor the ranking below applies (H4). When any game in the mode logged an SR change, the bar's value text also states the net SR swing (C2, `"+3 · +11%"`) — a 3-loss mode and a 3-loss mode aren't equally costly if one bled far more rank; absent when nothing in the mode logged a delta.
- **Mode cards are clickable (H4):** clicking one sets the ranking's mode filter to it (`prefs.mapModeFilter`) — the same pref the ranking's own mode-chip row reads/writes, so a card and its matching chip are always in sync — and scrolls the "Winrate by map" card into view. `.card--glow` marks whichever mode (card or chip) is currently selected.
- **Maps played donut:** share of games per map — the top 10 maps by games individually, the remainder rolled into one "Other (n maps)" slice. Slices carry a hover tooltip (label · games · share). Always shows every mode's maps together — the mode filter below scopes the ranking only, not this donut or the mode-cards row, both of which stay the one place to see the whole picture.
- **Winrate by map** horizontal bars: best → worst. The card is a `chartCard` with a **Chart/Table** toggle in the header, alongside two new filter rows (H4, `chartCard`'s `extraActions` slot):
  - **Mode chips** (`All` · one per `byMapType` key, `prefs.mapModeFilter`) — filters the ranking (`rankedMaps`-equivalent inline logic) via `makeMapMode(d.masterData.maps)`; `All` clears the pref rather than storing a sentinel value.
  - **Min-games chips** (`1+ · 3+ · 5+`, `prefs.minMapGames`, default `3` — same `MAP_MIN_GAMES`, `chip` + `prefs.set` + `store.rerender()` pattern as Heroes' and Players' own floor chips) — replaces the old fixed, uncontrollable 3-game floor. Maps below the active floor no longer vanish from the ranking (F4) — once at least one map in the current mode scope meets the floor, EVERY map still shows, sorted qualified-first (best → worst within each group), with the below-floor ones rendered dimmed (`horizontalBars`' `dimmed` row option: a muted bar colour and label/value text) and their own game count still visible, so nothing about the ranking is a cliff at the threshold. The subtitle states the active floor and, when any row is below it, how many — `"best to worst · 3+ games · 2 below the floor"` — or, when NO map in the current mode scope reaches the selected floor at all, the honest fallback `"no map has 3 games yet — showing all N · low sample"` (nothing dimmed in that case — the floor isn't meaningfully in effect over any row).
  - The table view (columns Map · **Mode** (H4) · WR · Net · **±SR** (C2, `Group.srNet` — a signed, rounded percentage, or "—" when the map logged no SR change) · Games · RTG, sortable) reflects the same mode/floor scoping as the chart.
- **Per-row meta (H4, `horizontalBars`' `meta` slot — renderer-side joins on map key, no core/contract change):** each bar (and, once the Table toggle is on, would read the same underlying scoped rows) can carry, on its own line under the bar:
  - a **▴/→/▾ trend glyph** (`trendArrow`, the same component Focus's own map rows and the Heroes table's Trend column use) — present only when `DashboardData.focusItems` (net-losing dimensions only, already the case before H4) carries a `dimension: 'map'` entry for this map with a `trend`; a winning/breakeven map simply has none, the same way Focus itself never discusses one.
  - a **⚑** when an active target is linked to the map (`focusItems`' `progress`), its tooltip naming the target and, once both windows have enough decided games, the winrate change since it was flagged.
  - a dimmed **"out of pool"** tag when master data marks the map inactive (`makeMapActive`) — an out-of-pool map used to rank among current ones with no cue that it can't be suggested for a new match.
  - The chart view deliberately does NOT also show the RTG self-rating average here (it did briefly, as a bare unlabeled number next to the winrate/games line, with nothing on screen saying what it meant beyond a hover-only tooltip) — a map with no other meta content (no trend, no linked target, in the pool) now correctly renders no meta row at all rather than a mystery digit. RTG stays a properly labeled, sortable column in the Table view only.
- **Chart tooltips:** the winrate bars use the shared cursor-following tooltip layer (with a native `<title>` fallback), the same pattern the scatter and donut use.
- **Highlight entry, guaranteed to land (H4):** navigated to with `{ highlight: <map> }`, the view scrolls that map's bar (or, in Table view, its first cell) into view (centered) and flashes it (`is-highlighted`, ~2.4s). The mode filter and the min-games floor are overridden for this render ONLY when the highlighted map would otherwise be hidden by them — never touching the persisted `mapModeFilter`/`minMapGames`, so the chip row still shows what's actually saved and a later visit isn't left on a filter the player never chose. Before H4, a 1-2 game map linked from anywhere else in the app could land on a floor-filtered Maps screen with no bar to flash at all, and the element search itself (`querySelectorAll('*')` as a catch-all fallback) could match the donut's own legend entry for the same map name instead of a ranking row; the fallback is now scoped to `.hbar-label`, a compact-bar label, or a table cell.

## Out-of-Scope

- Per-map drill-down or navigation (clicking a bar/row does not open anything — H4 only makes the MODE cards act as a filter, not the map rows themselves).
- Mode-level trends over time (owned by `screen-trends.spec.md`).
- A full-history reach or a second read for the trend/target/pool badges — they only ever show what's already on the loaded `DashboardData` snapshot for the active filter range.

## Constraints & edge cases

- `MAP_MIN_GAMES = 3` (shared with Focus's own map floor, exported from `src/core/analytics/focus.ts` — F1, no longer a locally duplicated `MIN_MAP_GAMES`) is the DEFAULT floor only now (H4) — `prefs.minMapGames` overrides it via the `1+ · 3+ · 5+` chips. The floor never hides a row (F4): with at least one qualifying map, below-floor maps coexist at the bottom, dimmed; with none qualifying, every map in scope shows at full weight and the subtitle says so plainly instead of implying a floor that isn't actually being applied.
- `TOP_SLICES = 10` — the donut shows at most 10 named slices plus "Other", unaffected by the mode/floor filters.
- Charts are dependency-free SVG; the tooltip layer and the table toggle are hand-rolled (guardrail #4). The mode/min-games chips and the per-row meta badges are plain HTML/CSS composed the same way every other chip row in the app is — no new chart primitive.
- A `highlight` for a map not present in the current FILTER RANGE at all (as opposed to merely below the mode/floor scope, which H4 now works around) simply doesn't flash anything — no error, no filter change.
- Map names are canonical (`src/core/maps.ts`); legacy raw GEP ids and older misspellings (e.g. the numeric `4140` that stands in for **Neon Junction**) normalize to their canonical name on load, so a map is never double-listed.
- **Net SR (C2)** never changes the win/loss tally or the ranking — only the `±SR` sum excludes placement-run matches (their SR swing isn't comparable to a normal match's, the same stance `sessionHistory` takes); the games themselves still count toward every other column.
