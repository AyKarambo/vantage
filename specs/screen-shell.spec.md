# Screen spec: Application shell (cross-screen behaviors)

**Source:** `renderer/src/app/shell.ts`, `renderer/src/app/palette.ts`, `renderer/src/fuzzy.ts`, `renderer/src/shortcuts.ts`, `renderer/src/gepStatus.ts`, `src/core/gepHealth.ts`, `src/main/gepStatusMonitor.ts`, `src/core/rankDisplay.ts` (`rankParts`), `renderer/src/components/toast.ts`, `popover.ts`, `skeleton.ts`, `dialogHeader.ts` (L5), `renderer/src/components/reviewControls.ts` (`bindTargetGradeKeys`, L5), `renderer/src/components/resultChooser.ts` (`bindSaveKeys`, L5), `renderer/src/app/log-match.ts`, `renderer/src/views/matchDetail.ts` (the match editor, L5), `renderer/src/format.ts` (`toDatetimeLocal`, `isToday`, L5), `renderer/src/store.ts`, `renderer/src/prefs.ts`, `renderer/src/main.ts`, `src/core/dashboardData.ts` (`matchSearchFilter`, `recentPlayers`, M5), `src/main/dashboard/reads.ts` (`searchMatchesRead`, M5), `renderer/src/views/players.ts` (`ViewParams.search` seeding, M5), `src/main/dataProvider.ts` (`editMatch`'s `playedAt`, L5), `src/store/history.ts` (`editManual`'s `timestamp` patch key, L5), `renderer/src/app/onboarding.ts`, `renderer/src/app/dataLocationPrompt.ts`, `renderer/src/components/overlay.ts` (`dismissOnBackdrop`/`dismissOnEscape`, F5), `renderer/src/views/faq.ts`, `src/core/demoPreference.ts` (`effectiveDemo`, F5), `renderer/src/components/icons.ts` (the sidebar/palette nav icon set, K6).

**Shared context:** The shell owns everything that is not a screen: the frameless titlebar, the sidebar (nav groups, Review pending badge, "Today's session" card), the global filter-bar host, the content host with the refresh model, and the status bar. Screens render from a `DashboardData` snapshot via `ViewContext` and never own global chrome. This is the referenced home for the shell-level behaviors the per-screen specs point at.

## Intent

One behavior layer that makes the app *feel* like a polished daily companion: a command palette so everything is reachable from the keyboard, a central shortcut registry with honest guards, a **truthful** connection indicator (attached ≠ alive), a toast/undo feedback layer, and a refresh model that never flickers loaded data away.

## Sidebar & navigation

- **Nav items** carry an `icon` that is either a text glyph or a **factory for an inline-SVG node** (`NavItem.icon: string | (() => Node)`, K6) — a factory rather than a prebuilt node, since a DOM node can only live in one place at a time and the same icon set is also reused for the command palette's Screen rows (see below); each call returns a fresh instance. 15 of the 17 nav items use a real SVG icon now, housed in `renderer/src/components/icons.ts` (built the way the original two — `targetsIcon`/`playersIcon`, moved there from `shell.ts` — already were: `currentColor`, CSP-safe, 24×24 viewBox, no font or CDN), replacing Unicode text glyphs that fell through to a system symbol font at an inconsistent weight (nine were geometric shapes from a small alphabet, five of those circles differing only by fill). Every nav button's `title` states the screen name plus its `Ctrl+<digit>` shortcut when it has one (K6) — the collapsed rail shows nothing else that could teach a shortcut, so hovering used to be the only way to even identify which icon was which screen.
- **Account chip** (top-left): pinned to an account, it shows that account with its rank composed through the shared rank renderer (`rankParts`) — the role, tier/division label, buffer/progress %, and a 🛡 shield when protected (no movement arrow; that's Overview-KPI-only); it falls back to the winrate heuristic only when the account has no anchor. Unpinned ("all accounts") the chip says the literal **All accounts** under a fixed `∗` glyph, and its sub-line attributes the most recently played rank to its account with short role/tier labels on one line (`Karambo · Dmg · GM4 · 16%`; the tooltip carries the FULL tier names — the sub-line is clamped to two lines, so the tooltip is the escape hatch that clamp depends on and deliberately does not shorten with it), or a plain account count when nothing is anchored (`renderer/src/sidebarChip.ts`, pure). Clicking the chip (`role="button"`, Enter/Space) opens an **account switcher** popover (the wide panel variant): a grid of ✓ · account · rank rows so names and ranks align, each row also carrying a muted **"N games · last played Xd"** line under the name (W2 — games from the filtered `byAccount` split, last-played from the unfiltered `accountActivity` map so a Role filter can't hide that an account was just played on a different role tonight), the active account expanded into aligned role · status rows, **All accounts** first, then every account **most-recently-played first** (W2 — not the alphabetical order `options.accounts` is sorted in), then **Manage accounts →** (jumps to Settings). Switching re-scopes the whole dashboard via the global account filter and re-points the rank line.
- **Sidebar order & collapse**: the top row holds the account chip and the `«`/`»` **collapse toggle** side by side (`.sidebar-top`); the nav scrolls in between; the **Current session** card is always the bottom-most element. The toggle (also `Ctrl B`) collapses the sidebar to a 60px icon rail — labels and the session card hide, the toggle stacks under the avatar, every nav item keeps its name as a tooltip. The collapse state is tri-state (W7, `sidebarCollapsed` pref — `'auto'` | `'open'` | `'collapsed'`): fresh-install default `'auto'` follows the window width, collapsed automatically below `SIDEBAR_NARROW_QUERY` (`matchMedia('(max-width: 1180px)')`, shell.ts) and expanded above it, so a Win+Left/Right half-1080p snap (paired with `minWidth: 960`, `dashboardWindow.ts`) never leaves the nav a keyhole; clicking the toggle or `Ctrl+B` always PINS an explicit `'open'`/`'collapsed'` from then on, opting out of the width-driven behavior (today's sticky-boolean toggle, unchanged in spirit — there is no UI path back to `'auto'` short of clearing the pref). A legacy boolean value migrates once on read (`true` → `'collapsed'`, `false` → `'auto'`). Below `1100px`, `.content` padding tightens and the Overview scatter's `.scatter-callouts` column narrows from 250px to 200px (`app.css`) so the chart itself keeps more of the width.
- **Current session card** (S3, `DashboardData.session` — the trailing gap-based sitting that's still open, follows the account switcher but not the role/date filter): active state shows `W–L` · signed net · winrate on one line, then a second line with the streak (`W3`/`L2`/`–`, win/loss-tinted) and the top map (`<map> ×N`) when known — the whole card is a keyboard-reachable button (`role="button"`, Enter/Space) that opens Matches scoped to the sitting's day (`{ day }`). Empty state names the actual rule instead of a bare "no session" line — `"No games in the last <gap>h — your next game starts a new sitting"` — derived from the user's `sessionSettings.gapMinutes` (Settings → Coaching); both states carry the gap rule and the role/date-filter caveat in a tooltip. Once the sitting **closes**, this card returns to its empty state and the Overview's last-session debrief takes over (`screen-overview.spec.md`) — the two never show the same sitting at once.

## Command palette (`Ctrl+K`, or the titlebar "Search or log a match" button)

- Item groups, in curated default order: **Action** (Log match · Keyboard shortcuts · Replay the intro tour · Report a bug · the Settings/Logs/Winrate-colours toggles below, M5), **Screen** (every sidebar entry, each carrying its `Ctrl+<digit>` as a `.kbd` hint when it has one, M5, AND the same sidebar icon a fresh instance of, K6 — `PaletteNav.icon`, built once per palette open in `shell.ts` from the same `NavItem.icon` factory the sidebar itself calls, never the sidebar's own live node), **Map** (each map → that map's own games on Matches, `{ map }`, H3), **Hero** (each hero with stats → hero drill-down drawer), **Target** (every target, self/measured mode + archived/inactive noted in the hint, → `targetDetail`, M5), **Player** (a small ≤30-row snapshot slice, `DashboardData.recentPlayers` — games-together in the hint → `playerHistory`, M5), **Match** (the 30 most recent rows → match detail; hero names, game type, and account are matchable keywords).
- Hand-rolled fuzzy ranking (`fuzzy.ts`), max 12 snapshot results; the empty query shows the curated order with actions first, so `Ctrl+K` → `Enter` still logs a match.
- **Reaching past the snapshot (M5):** any non-empty query additionally appends a synthetic `Find player "<q>" on Players` item (**Player** group, unconditional — the cheap first step for a player outside the small `recentPlayers` slice) that runs `ctx.navigate('players', { search: q })`; `ViewParams.search` (an `'effect'` param — a one-shot seed, not a route) seeds the Players screen's own search box and triggers its normal load on arrival, applied at most once per distinct navigation so it never fights a player's own later edit or clear. Separately, once the query is 3+ characters AND the synchronous snapshot came up under 12 hits, a debounced (200ms) `bridge.searchMatches({ filters, q, limit: 8 })` reaches the FULL filter-scoped history (map, hero, account, a roster player's name, or the date — `matchSearchFilter`, `src/core/dashboardData.ts`, pure and unit-tested) and appends its rows under an **All history** group once it resolves — guarded against a stale response (the query moved on, or the palette closed) painting late.
- Fully keyboard-driven: type to filter, ↑/↓ to move (wraps), Enter to run, Escape closes; mouse hover moves the selection. Guarded against double-open; opens only once a data snapshot exists.
- **Listbox semantics (K3):** the input carries `role="combobox"` + `aria-expanded="true"` + `aria-controls="palette-listbox"` + `aria-autocomplete="list"`; the result list is `role="listbox"` (a hardcoded `id="palette-listbox"`, safe since only one palette can ever be open at once); each row is `role="option"` with a `palette-option-<i>` id and `aria-selected` tracking the keyboard/mouse selection. The input's `aria-activedescendant` is set to the selected row's id on every paint (never moving DOM focus off the input itself), and the selected row is scrolled into view (`scrollIntoView({block:'nearest'})`) alongside it — a screen reader and a long, scrolled result list both stay in sync with ↑/↓ the same way a native combobox would.
- **Settings/Logs/Winrate-colours/Density actions (M5, density W7):** "Settings: MCP endpoint", "Settings: Live kill feed", "Settings: Break reminder", "Settings: Demo data", "Logs: Debug detail", one action per winrate scheme ("Winrate colours: Aurora" / "Teal & coral" / "Colorblind"), and one per density ("Density: Comfortable" / "Compact") — each calls the exact setter its own Settings/Logs/Appearance card calls (`setAppSettings`, `setBreakReminder`, `setLogLevel`, `setWinrateScheme`, `setDensity`), so the two can never drift, and toasts the applied state on run (the density actions skip `store.rerender()` — the effect is a pure CSS attribute, same as the Appearance card's own control). Current state (`getAppSettings`/`getLogLevel`/`getBreakReminder`, plus the renderer-local `getWinrateScheme`/`getDensity`) is fetched once per palette open so each hint reads `currently on`/`currently off` (blank when that option isn't the active one) rather than a bare action name. Unfiltered results are capped (`fuzzy.ts`'s snapshot limit), so a specific action past the cap needs a query to surface — typing "Density" finds both density actions the same way any other filter does. `palette.ts` itself stays generic — these are ordinary `extras.actions` entries the shell builds, nothing palette-specific.

## Shortcut registry (`shortcuts.ts`)

- Declarative bindings (`combo`, `description`, `group`, optional `when` / `allowInInput` / `hidden`) dispatched by one window `keydown` listener. Guards on every binding: never fires while an input/textarea/select/contenteditable has focus, and never while an overlay or popover is open — except bindings marked `allowInInput` (Ctrl+K, Ctrl+L).
- Registered by the shell: `Ctrl+K` (palette), `Ctrl+L` (**log a match**, L1 — opens the same modal as the palette's own Log match action and the titlebar's `+ Log match` button, in one step from anywhere; `allowInInput` so it reaches from inside a field like Ctrl+K, but still gated behind its own `when: () => !overlayCapturing()` — unlike Ctrl+K, firing it directly opens a modal, so it must not stack a second one on an already-open overlay), `?` (cheatsheet), `Ctrl+B` (collapse/expand the sidebar), `Ctrl+=`/`Ctrl+-`/`Ctrl+Shift+0` (**text-size zoom**, W7 — step / reset; see `screen-settings.spec.md`'s App behavior card for the persistence and clamp details), `Ctrl+1…9` and `Ctrl+0` (screen jumps — each digit is declared on its own `NavItem.key`, not derived from sidebar position, so reordering or inserting an item never renumbers the others; a screen with no `key` simply has no digit shortcut, and a duplicate digit is dropped rather than shadowing — `Ctrl+0` is Players, which is why the zoom reset uses `Ctrl+Shift+0` instead), `Escape` and `Alt+←` (**back** — the previous screen on the session stack, from anywhere; suppressed while an overlay/popover/palette is open, which keeps `Escape` for its dismissal), `←`/`→` (older/newer match, only on a match detail). The mouse back button (`MouseEvent.button === 3`) is bound to the same action outside the shortcut registry. The Review screen registers `H`/`P`/`M`/`S` (see `screen-review.spec.md`).
- **Titlebar (L1):** the center pill splits into a `Ctrl K · Search` button (opens the palette) and a `+ Log match · Ctrl L` button beside it (opens the log-match modal directly) — previously one combined "Search or log a match" pill that still needed the palette plus Enter to actually log anything.
- **Cheatsheet ordering (`shortcutGroups()`, M5):** groups render in a fixed `GROUP_ORDER` (`Global`, `Navigate`, `Review`, `Log match`; an unlisted group falls in after, in whatever order it happened to register) — NOT raw registration order, which used to lead the cheatsheet with `Log match`/`Review` (context-only groups that register at their module's plain import time) ahead of `Global`/`Navigate` (which only register once the shell's own `bindGlobals()` runs). Within `Navigate`, rows additionally sort by their own `Ctrl+<digit>`, `0` sorted last rather than wherever `NAV` happened to declare it (Players' `Ctrl+0` used to land mid-list, between two single-digit screens) — every non-digit Navigate binding (Escape, the match-detail arrow-key stepper, …) keeps its registered order after the digits. Unit-tested (`test/shortcuts.test.ts`).
- The `?` cheatsheet overlay renders itself from the registrations, grouped and ordered as above, with comfortable padding and aligned key badges (`.kbd`) — the same `.kbd` chip the palette's own `Screen` rows and literal-shortcut `Action` rows (Log match, Keyboard shortcuts) now render their hint as (M5), instead of plain hint text indistinguishable from a note like "on the About screen".

## Status-bar connection indicator

- Dot + label rendering the four-state model from `src/core/gepHealth.ts` (`no-game` · `connected` · `live` · `stale`) with truthful labels: "No game" · "Connected — waiting for events" · "Receiving data" · "⚠ No data for Ns" (stale, with live seconds-of-silence). A non-GEP sensor (`counterwatch`, demo/no-live-feed runs) always renders the no-game dot with "No live feed" — it can never claim Connected or Live.
- Click opens a live-updating details popover (S6): the last error first, in a warning tone, when one is present; then state, source (GEP vs. counterwatch), the loaded GEP package version, last event (relative time), events this session, match-in-progress flag, and feed attach time. A footer of next steps — **Logs →**, **Alerts…** (Settings), and **Open Live →** while a match is in progress — replaces what used to be a diagnostic dead end. Relative times re-render on a 10s tick while open.
- Renderer mirror (`gepStatus.ts`): one snapshot pull at startup and on window focus, then push updates over `onGepStatus`. The main-process monitor re-evaluates on every feed signal and on a 15s tick; every transition is logged and mirrored onto the tray icon + tooltip.
- The app-wide `.gep-banner` (top of content, above the filter bar) shows, in priority order: a "restart to apply" prompt while a GEP fix is staged, an outage explanation while Overwolf's service is degraded/down, or — lowest priority, S6 — a "feed's gone quiet" heads-up while `state === 'stale'`, with an **Open Logs →** action. The Live screen also prepends its own inline version of the last one, next to the scoreboard it's warning about, and subscribes to `gepStatus` so it appears/clears live rather than waiting for the next unrelated repaint.

## Toast + undo layer (`components/toast.ts`)

- One host stacking toasts bottom-right, `aria-live="polite"`; default TTL 6s (floor ≥5s), hover pauses the timer; optional single action button. Reversible actions execute immediately and offer **Undo** (review save, target archive, rank/settings changes); only permanent target delete and account-data deletion keep a confirmation modal.

## Flicker-free refresh model (`store.ts` + content host)

- Cold start renders skeleton cards; every later refetch (filter change, window focus, manual retry) keeps the current snapshot rendered with a small busy indicator until the new one lands. A failed background refresh keeps the stale data with a "⚠ stale — retry" link; a failed cold start renders an inline error card with **Retry**.
- The content host re-renders only when the snapshot, route, params, or an explicit `rerender()` epoch changes — status-bar-only updates never redraw the content. Window focus triggers a background refetch (stale-while-revalidate for newly tracked games).
- **A same-route refresh (only the snapshot changed) is deferred, never dropped**, in two cases (K2, GitHub issue #197 — "Make in-app text selectable"): while the user is actively PRESSING inside the content host (`contentPressed`, flushed on `pointerup`/`pointercancel` — replacing the pressed element mid-click makes the browser drop the click, since a native click needs its down/up to share a target), and while a non-collapsed text SELECTION sits inside the content host (`hasSelectionInContent()`) even with nothing currently pressed — the scenario a plain press-guard alone missed: select some text, alt-tab away to paste it, come back, and the window-focus refetch used to silently wipe the selection with no press involved at all. The selection case flushes on `document`'s `selectionchange` event once the selection collapses or moves outside the content host, independent of the press-release path. Route/param/epoch changes always render immediately regardless of either guard.

## Global filter bar (`views/view.ts` `filterBar`, rendered above every screen)

- **Role · Season** selects. There is no Mode filter (the app is competitive-only everywhere) and no Account control in the bar (account selection lives in the sidebar switcher; `account` stays in filter state/IPC, just not as a bar control). Persisted across launches (`vantageFilters` localStorage); old persisted `mode` keys are ignored on load.
- **Season entries:** `Last 7 days`, `Last 30 days`, one entry per season with ≥1 competitive match (current season always included), newest first, then `All time` (`src/core/season.ts`).
- **Reset chip:** when any filter differs from the defaults (role=all, days=30), a "Reset (N)" chip restores the defaults in one click (the active account is left untouched — that's the switcher's job).
- **Presets:** up to 2 saved filter combinations as one-click chips (auto-named, e.g. "Support · 30d"); "+ save preset" appears while the current combination is non-default and unsaved; right-click removes a preset. Persisted via `prefs.filterPresets`.
- **Per-view suppression:** `FILTERLESS_VIEWS` in `shell.ts` (`readiness`, `about`, `playerHistory`, `faq`, `live`) hides the filter bar for a view whose data is intentionally unscoped by any filter or the account switcher (see `readiness-score-rework.spec.md`).

## View restore, scroll memory & status text

- The active top-level view persists (`prefs.view`) and is restored on launch; a parameterized drill-down persists as its `DETAIL_PARENT` (a match detail as `matches`, a player as `players`, a target detail as `targets`), so the app never reopens on a drill-down. `DETAIL_PARENT` also drives which sidebar item highlights while a drill-down is open, and the restorable set is compiler-checked (`RESTORABLE` in `store.ts`).
- **Back stack:** the store keeps a bounded (20) session trail of the routes behind the current one, pushing the OUTGOING route on every `setView` and collapsing runs within one view (so 200 arrow-key steps through match details leave one entry). It is never persisted. Back pops to the newest entry that still resolves — a match is only "gone" on positive evidence of deletion, never on absence from the filter-scoped list — and one-shot ("effect") params (`highlight`, `prefillName`, `prefillRole`, `prefillHeroes`, `prefillMap`, `editTargetId`, `section` — Settings' section-rail deep link, W1) are stripped at push time so going back cannot re-issue a command; `PARAM_KINDS` in `backStack.ts` is the compiler-checked source of truth for the full set. The pure reducer is `renderer/src/backStack.ts` (`test/backStack.test.ts`).
- Per-route scroll positions are remembered in-session and restored when navigating back (notably Matches ↔ matchDetail); a data refresh on the same route keeps the current scroll.
- Status text "N games · updated Xm ago" is re-derived every 60s while idle, so the relative time never lies. Says nothing about demo data (F2) — that would double up the sidebar's own "Demo data" badge, which is now a real button (title "Sample season — click to turn demo data off") navigating to Settings' App behavior card instead of a static span.

## Quick-log modal (`app/log-match.ts`, opened from the Overview CTA, the titlebar's `+ Log match` button, `Ctrl L`, or the palette's Log match action)

- Prefills **role** from the last logged match (`prefs.logPrefill`); result/map/hero always start fresh; mental flags start empty. Every quick-logged match is sent as `gameType: 'Competitive'` (there is no mode picker).
- The hero field is a typeahead over the canonical hero list (`src/core/heroes.ts`) plus any hero already in the player's data; free text stays allowed.
- **Map field (`components/mapPicker.ts`, L4):** a strict combobox — the committed value can only be a real map name (`resolveMapName`). The typed-query pool is ranked by `fuzzyRank`, not prefix/contains matching, so a typo, a missing apostrophe or a missing accent ("kings row", "esperanca") still surfaces the real map; `fuzzyScore` itself folds diacritics both ways so an unaccented query matches an accented name. On blur, an exact match commits as before; failing that, text that `fuzzyRank` resolves to exactly one candidate auto-commits to it (uniqueness is the safety net — genuinely ambiguous text is never force-resolved); otherwise the field **keeps the typed text** (it no longer silently reverts to blank), gets an `is-invalid` style, and shows the "isn't a known map" hint immediately via `onInvalid` — not only after a failed Save attempt.
- **Hero shortlist (`components/heroPicker.ts`, L4):** a "most played" pool shorter than the caller's intended size — a fresh account, or a role never queued on this account — is padded out with the rest of the role-eligible pool, alphabetically (`padShortlist`), so the grid always opens usable instead of empty and forcing every hero to be typed into search.
- Active improvement targets are listed with optional inline 3-way grading; a competitive log can also enter the match's SR %. **Keyboard grading (L5, shared with the match editor):** `↑`/`↓` moves a purple `.is-focused` outline across the target rows (starting on the first one) and `H`/`P`/`M` grades whichever is focused, advancing to the next row afterward (unless it's the last one) — `components/reviewControls.ts`'s `bindTargetGradeKeys`, the same model the Review screen itself uses. No active targets shows a **"No active targets — add some on the Targets page."** hint in place of the block rather than dropping the block outright, so the form's layout doesn't reflow around whether any happen to exist.
- "Save ⏎" and "Save & next Ctrl ⏎" (reopens for the next game, prefilling this game's heroes and — when it was itself backfilled — its own Played instant, L5, see below); saving refreshes the dashboard and shows a toast naming what was actually stored (L3) — "Match logged — Loss · Oasis · Climb Damage · −25%" — with an **Undo** action (the shared `deleteMatch` from `matchActions.ts`, so the undo itself stays reversible and the back stack is told). Undo is omitted when the save also anchored a first rank or wrote a placement prediction, since `deleteMatch` only unwinds the match record, not those. A hand-logged match gets no OS notification (the player is already looking at the toast that just said more); an auto-tracked (GEP) match never had a "Match logged" OS banner to begin with. **Enter-to-save (`components/resultChooser.ts`'s `bindSaveKeys`, shared with the editor, L5):** Enter saves from anywhere but a focused button, Ctrl/Cmd+Enter saves & logs another — the editor passes no `saveAndNext`, so its own Ctrl+Enter falls back to plain save instead of no-op'ing.
- **Silent account switch, named (L3):** when a match auto-switches the scoped account filter (the app-wide rule in `screen-settings.spec.md`), a short "Now showing `<account>`" toast follows it — manual logs only; a live-tracked switch fires while the player is still in Overwatch, looking at neither Vantage nor a toast.
- **Layout (L2):** the header and the Save row are both `position: sticky` within the card's own scroll — the header pins to the top, the Save/Save & next row to the bottom — so both stay visible on a card taller than the window, instead of the whole card scrolling as one block with the header and the save buttons both off-screen at once. `components/dialogHeader.ts`'s `dialogHeader` builds this header (L5, shared with the match editor): title left, then caller-supplied `extra` controls (the log card's **Account** select; the editor's read-only `<map> · <role>` label), the provenance badge, and the `.overlay-close` ✕. The left column is Result → Map → Role → Heroes → Skill rating (the fields touched on every log); the right column is Performance → Comms → Flags → Targets → **Played** (the backfill control, used far less often than the fields above it). The match-detail editor's own Save/Cancel row gets the same sticky-footer treatment (`views/matchDetail.ts`), and its header/footer now sit OUTSIDE the padded body the same way the log card's do, rather than a single padded root with a negative-margin hack to cancel it just for the footer.
- **Played backfill (L5):** five chips — **Just now / 30m ago / 1h ago / 2h ago / Other…** — the first four snapshot an absolute timestamp at click time (so it never drifts while the form sits open); **Other…** reveals a `<input type="datetime-local" max=now>` (`format.ts`'s `toDatetimeLocal`/`isToday`) seeded from whatever instant is already chosen, for a session logged the next morning or a game from 3-4 hours back that no relative offset can honestly reach. The header badge switches from a bare `hh:mm` to `dateLong · hh:mm` the moment the chosen instant isn't today, so a backfill across midnight has a visible date cue instead of silently landing on the wrong day. **Carried forward by Save & next:** the LogCarry the next form opens with includes the just-saved match's own `playedAt` (when it was itself backfilled — "Just now" carries nothing, since there's no backfill to preselect a starting point for), so a missed SESSION doesn't mean re-clicking the same offset chip, each measured from an ever-later "now", on every single form — the next form opens with **Other…** already active on that exact instant, for the player to nudge forward by hand.
- **Editable on the match editor too (L5, `views/matchDetail.ts`):** a **Played** `datetime-local` field sits under Role in the facts block — hand-logged matches only (`d.source === 'manual'`); a GEP capture's timestamp is the instant the game itself ended and stays locked, same as every other auto-tracked fact. Saving sends `MatchEditInput.playedAt` only when it actually changed; main honours it only for a manual match (`src/main/dataProvider.ts`'s `editMatch`, defense-in-depth alongside the editor's own gate), clamps it to the past, patches `HistoryStore.editManual`'s new `timestamp` key, and re-runs `syncRankAtStart` (write-once, same "no-op once a snapshot already stands" rule role edits already had) since the snapshot is time-ordered. Correcting the instant re-sorts the match into its new day/session position everywhere — the Matches list's day grouping, the detail page's own day-strip stepper (M4), rank-at-start — since nothing downstream memoizes on the old timestamp.
- SR/%-into-division fields share a wheel nudge (±1 per tick, **Shift for ±5**, tooltip "Scroll to nudge ±1 · Shift for ±5") — the quick-log SR field, the Set-current-rank picker, the match editor's, and the placement-completion dialog's % field all go through the same `nudgedInput` (`components/srControls.ts`).

## First-run flow & help surfaces (F5)

- **Sequence on a fresh install** (`shell.ts`'s `maybeFirstRun`): the data-location choice (`app/dataLocationPrompt.ts`, only when `getDataLocation().needsFirstRunChoice`) runs first because it must complete before meaningful data is written (spec C1/C4 in `screen-settings.spec.md`), then the intro tour (`app/onboarding.ts`) — its own second step folds in the demo-data choice when `demoPreference` is still `'unset'`, rather than a separate blocking prompt immediately beforehand that the tour would otherwise restate. "What's new" only shows on a launch where the tour didn't just run.
- **Four steps** (down from seven, F5): (1) welcome + the account-safety promise; (2) **"Your workspace"** — one line per screen, grouped the way the sidebar is (`onboarding.ts`'s own `WORKSPACE` table, hand-kept in step with `NAV` above rather than generated from it — NAV items carry no blurb text, and NAV's `App` group isn't "your workspace"), with the demo-data choice folded in on a genuine first run (its two buttons — **Show me demo data** / **Start fresh** — replace Next; either advances to step 3); (3) the log/review loop, stating the real `Ctrl+L` shortcut; (4) Notion sync + support, reading the support address from `getAppInfo().supportEmail` (a literal fallback only until that promise resolves, same pattern as About). A replay (Help menu below, or the FAQ screen's own button) always passes `offerDemoChoice: false` — the choice is already made, so step 2 is just the workspace rundown with normal Back/Next; the status bar's "Demo data" badge is the persistent answer to "am I looking at real games", so the tour doesn't restate it on replay.
- **`openModal`'s two dismissal options** (`components/overlay.ts`, F5): `dismissOnBackdrop: false` suppresses backdrop-click dismissal; `dismissOnEscape: false` additionally suppresses Escape. Both default `true` (existing callers unaffected). The data-location prompt sets both `false` — no safe "just walked away" default exists for it; the intro tour leaves both at their default (Escape/✕ simply skips it, same as before — a demo choice left unmade this way reads as `'off'` functionally, `effectiveDemo` in `src/core/demoPreference.ts`, and is fully recoverable from Settings any time).
- **FAQ (`views/faq.ts`):** a filter input in the `viewHead` (`.search-input`, live on every keystroke, case-insensitive substring over question + answer text) narrows every topic card to matching Q&As, hiding a topic card entirely once nothing in it matches, and showing a plain "No FAQ entries match …" in place of all of them when nothing anywhere does. Three new topics beyond the original five — **Accounts & ranks** (rank anchors, placement runs, the `Unknown` bucket), **Demo data**, **Coaching nudges** (break reminder vs. the stop rule) — each with a jump link to the screen that owns the behavior; **AI coach (MCP)** already existed (W4). The **What's new** card collapses to the `WHATS_NEW_COLLAPSED` (2) most recent releases with a **Show all (N) →** link expanding the full history in place; hidden once nothing more is hidden. The support email is read from `getAppInfo().supportEmail`, same fallback-then-resolve pattern as onboarding and About.

## Accessibility, motion & error forwarding

- Visible `:focus-visible` rings on interactive elements; `prefers-reduced-motion` disables transitions/animations.
- **Tab trap parity (K3):** `openPopover` (`components/popover.ts` — the account switcher, connection-status details, and every other anchored popover) now sets `document.getElementById('app')` `.inert = true` while open and `false` on close, the same trap `mountOverlay` (`components/overlay.ts`) already used for centered modals and the right drawer — Tab could previously walk out of an open popover into the dimmed sidebar/filter bar behind it, since the popover had a `role="dialog"` panel but nothing actually keeping focus inside it.
- Uncaught renderer errors and unhandled rejections are forwarded over `logRendererError` into the main-process release log, so field problems are diagnosable from the Logs screen.

## Out-of-Scope

- Tray-icon rendering and window-bounds/close-to-tray mechanics — main-process (surfaced in `screen-settings.spec.md`).
- Palette search across full history is now in-scope for matches (M5, see the palette section above) — a query 3+ characters that comes up under 12 snapshot hits reaches `searchMatches` over the full filter-scoped history, not just the 30 most recent rows. Still out of scope: a similar full-history reach for the **Player**/**Target** groups (both stay snapshot-only — `recentPlayers`'s ≤30-row slice and `d.targets`; the "Find player on Players" fallback is the one path to a player outside that slice) and ranking the async `All history` results against the synchronous ones (they're simply appended after, never interleaved by relevance).
- Light theme, responsive/mobile layout, localization.
- Open Queue's hero grid stays one flat list rather than grouping into Tank/Damage/Support sections with a role-icon header (L4 proposed this; only the empty-shortlist padding shipped — Open Queue already has no "most played" ranking to fall back on, so it degrades to the same alphabetical full-pool grid every other under-sized shortlist does, just ungrouped).

## Constraints

- **Guardrail #4 (CSP, single bundle):** the fuzzy matcher, palette, popover, toasts, and skeletons are hand-rolled `components/` primitives — zero new runtime dependencies.
- Connection staleness derives only from sanctioned GEP signals (guardrail #1); the state model is pure and Electron-free in `src/core/gepHealth.ts` (`STALE_AFTER_MS = 60_000`), unit-tested. The staleness clock runs only while a match is in progress; `live` is only ever shown mid-match with recent events.
- All shell UI preferences (view, log prefill, presets, recap-shown, winrate scheme) go through the one typed `prefs` facade over localStorage; storage failures degrade silently to defaults.
- The preview harness simulates all four connection states via `?gep=live|stale|connected|no-game` (or `?gep=cycle`).
